# Data Model

**Target:** SQLite via SQLAlchemy in the Mock HMS (`mock_hms/models.py`).
**Bar for "done":** every field, type, constraint and relationship needed to write the Phase 3 schema is decided here. No new modelling decisions later.

---

## Entity relationship overview

```
Department 1 ──< Doctor 1 ──< Slot 1 ──0..1 Appointment >── 1 Patient
                    │                          │
                    └──< DoctorUnavailability   ├──< Notification
                                                └──< AppointmentAudit
```

Read as:
- A **Department** has many **Doctors**.
- A **Doctor** has many **Slots** (their bookable calendar) and many **DoctorUnavailability** periods.
- A **Slot** holds at most one active **Appointment**. This one-to-one is the double-booking guard.
- A **Patient** has many **Appointments**.
- An **Appointment** has many **Notifications** (confirmation, T-24h, T-2h, change notices) and many **AppointmentAudit** rows.

## 1. Department

**Seed:** 3 departments — Cardiology (`CARD`, 20 min), Orthopaedics (`ORTHO`, 30 min), General Medicine (`GEN`, 15 min).

## 3. Patient

| Field | Type | Constraints | Notes |
|---|---|---|---|
| `patient_id` | INTEGER | PK, autoincrement | |
| `mrn` | VARCHAR(20) | UNIQUE, NOT NULL | Medical record number, `MRN-00001` |
| `full_name` | VARCHAR(100) | NOT NULL | |

| `email` | VARCHAR(120) | NULL, indexed | Nullable — not every patient has one |
| `date_of_birth` | DATE | NOT NULL | Drives `is_senior` |
| `gender` | VARCHAR(10) | NOT NULL | `M` / `F` / `O` |

> **Dedup rule:** `phone` is the unique lookup key used by the Scheduling Bot. Name matching is advisory only and never auto-merges — near-matches go to the exception queue.

## 4. Slot

A single bookable unit on one doctor's calendar. Slots are pre-generated by `seed.py` for a rolling 30-day horizon.

| Field | Type | Constraints | Notes |
|---|---|---|---|
| `slot_id` | INTEGER | PK, autoincrement | |
| `doctor_id` | INTEGER | FK → `Doctor`, NOT NULL, indexed | |
| `slot_date` | DATE | NOT NULL, indexed | |
| `start_time` | TIME | NOT NULL | |
| `end_time` | TIME | NOT NULL | `start_time + consult_minutes` |
| `status` | VARCHAR(15) | NOT NULL, default `AVAILABLE` | See status values below |
| `is_emergency_reserve` | BOOLEAN | NOT NULL, default FALSE | Last 2 slots/day, urgent cases only |
| `locked_until` | DATETIME | NULL | Optimistic lock held by the Scheduling Bot |
| `locked_by` | VARCHAR(50) | NULL | Bot/robot identifier holding the lock |
| `version` | INTEGER | NOT NULL, default 0 | Incremented on write; concurrency guard |

**`status` values:** `AVAILABLE` · `LOCKED` · `BOOKED` · `BLOCKED` (doctor unavailable) · `COMPLETED` · `NO_SHOW`

**Constraints:**
- `UNIQUE (doctor_id, slot_date, start_time)` — a doctor cannot have two slots at the same instant.
- Partial unique index: at most one non-cancelled `Appointment` per `slot_id`. **This is the database-level double-booking guard.**

|---|---|---|---|

| `reference_no` | VARCHAR(20) | UNIQUE, NOT NULL | `APT-2026-000123`, shown to the patient |
| `patient_id` | INTEGER | FK → `Patient`, NOT NULL, indexed | |
| `slot_id` | INTEGER | FK → `Slot`, NOT NULL, indexed | |
| `doctor_id` | INTEGER | FK → `Doctor`, NOT NULL | Denormalised for query speed |

| `priority` | VARCHAR(10) | NOT NULL, default `NORMAL` | `URGENT` / `HIGH` / `NORMAL` |
| `reason` | VARCHAR(255) | NULL | Patient-stated reason for visit |
| `is_follow_up` | BOOLEAN | NOT NULL, default FALSE | Priority weighting input |
| `previous_appointment_id` | INTEGER | FK → `Appointment`, NULL | Set when rescheduled; links the chain |
| `source` | VARCHAR(20) | NOT NULL, default `BOT` | `BOT` / `MANUAL` / `RESCHEDULE` |
| `queue_item_ref` | VARCHAR(50) | NULL | Orchestrator queue item id — bot traceability |
| `booked_by` | VARCHAR(50) | NOT NULL | `SchedulingBot` / clerk username |
| `created_at` | DATETIME | NOT NULL, default now | |
| `updated_at` | DATETIME | NOT NULL, on update now | |
| `synced_to_excel_at` | DATETIME | NULL | NULL = not yet mirrored; drives reconciliation |

**`status` values:** `SCHEDULED` · `CONFIRMED` · `RESCHEDULED` · `CANCELLED` · `COMPLETED` · `NO_SHOW`

**`priority` derivation** (computed at booking time, recorded here):
`URGENT` if request flagged urgent · else `HIGH` if `patient.is_senior` or `is_follow_up` · else `NORMAL`.

## 6. Notification

One row per send attempt — not per appointment. The Reminder Bot reads this to know what has already gone out.

| Field | Type | Constraints | Notes |
|---|---|---|---|
| `notification_id` | INTEGER | PK, autoincrement | |
| `appointment_id` | INTEGER | FK → `Appointment`, NOT NULL, indexed | |
| `patient_id` | INTEGER | FK → `Patient`, NOT NULL | |
| `type` | VARCHAR(20) | NOT NULL | `CONFIRMATION` / `REMINDER_24H` / `REMINDER_2H` / `RESCHEDULE` / `CANCELLATION` |
| `channel` | VARCHAR(10) | NOT NULL | `SMS` / `EMAIL` |
| `recipient` | VARCHAR(120) | NOT NULL | Phone or email as sent |
| `template_id` | VARCHAR(30) | NOT NULL | e.g. `TPL_REMINDER_24H_EN` |
| `body_preview` | VARCHAR(255) | NULL | First 255 chars, for the audit trail |
| `status` | VARCHAR(15) | NOT NULL, default `PENDING` | `PENDING` / `SENT` / `FAILED` / `SKIPPED` |
| `provider` | VARCHAR(20) | NULL | `TWILIO` / `SENDGRID` |
| `provider_message_id` | VARCHAR(64) | NULL | Gateway-returned id |
| `attempt_no` | INTEGER | NOT NULL, default 1 | Retry counter |
| `error_code` | VARCHAR(50) | NULL | Gateway error on failure |
| `sent_at` | DATETIME | NULL | |
| `created_at` | DATETIME | NOT NULL, default now | |

**Constraint:** `UNIQUE (appointment_id, type, attempt_no)` — prevents accidental duplicate reminders on a bot re-run.

> **Idempotency rule:** before sending, the Reminder Bot checks for an existing row with the same `appointment_id` + `type` and `status = SENT`. If found, it skips. This is what makes the bot safe to re-run.

## Excel mirror — `data/appointments.xlsx`

The second "system" the bots reconcile against. Flat sheet, one row per appointment.

| Column | Source |
|---|---|
| `ReferenceNo` | `Appointment.reference_no` |
| `PatientMRN` | `Patient.mrn` |
| `PatientName` | `Patient.full_name` |
| `Phone` | `Patient.phone` |
| `Department` | `Department.name` |
| `DoctorName` | `Doctor.full_name` |
| `AppointmentDate` | `Appointment.appointment_datetime` (date part) |
| `AppointmentTime` | `Appointment.appointment_datetime` (time part) |
| `Status` | `Appointment.status` |
| `Priority` | `Appointment.priority` |
| `BookedBy` | `Appointment.booked_by` |
| `SyncedAt` | Write timestamp |

**Reconciliation key:** `ReferenceNo`. A row in one system and not the other, or a status mismatch on the same reference, raises an `EXCEL_MISMATCH` conflict.
